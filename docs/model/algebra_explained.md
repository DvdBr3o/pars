# 𝔖′ 通俗版：四个小例子看懂"一个同态"

> 配套 `docs/model/algebra.md`。只用四个具体例子，说明"解析 = 前缀积"，
> 以及四种可压缩 schema 各自长什么样。不需要看代码。

## 例子 0：所有并行都来自同一件事

把输入切成一段一段，如果你能用一个**结合**的操作 `⊗` 把相邻两段的"摘要"合并成
一大段的摘要，那么整段输入就可以用**并行前缀和**（treap 式，树上归约）算出来，
深度只有 `log n`。

> 摘要 = "这段输入对解析器来说意味着什么"。`⊗` 结合 = 可以从任意位置先合并。

不同的文法，差别只在**摘要长什么样、`⊗` 是什么**。下面四个 schema 就是四种摘要。

---

## 例 1 `finite`（正则 / 有界状态）：JSON 字符串

输入 `a " b " c`，问：每个字节之前，"在不在字符串里"？

- 摘要：这段字节把"入口状态（0=外/1=内）"变成"出口状态"的一个**函数**，
  用两个比特 `f(0), f(1)` 表示。
- `⊗`：函数复合（先走 A 再走 B）。
- 单个字节 `"` 的函数是"翻转"，普通字符是"保持"。

算前缀积（前缀复合）就得到每个位置的处理前状态：

```
字节:        a      "      b      "      c
quote 掩码:  0      1      0      1      0
前缀积=XOR:  0      0      1      1      0   →  在字符串内 = 0 0 1 1 0
```

`prefix_xor` 就是这个"翻转函数"的前缀积——simdjson 的 `prefix_xor`、cuJSON 的
escape scan 都是它的特例。**这就是旧 R1–R4 的全部内容。**

---

## 例 2 `stack`（visibly-pushdown）：括号配对

输入 `( ( ) )`（下标 0–3），问：谁和谁配？

- 摘要：一段的"未配对括号"——`(close, open)` 两个计数（单括号类型时）。
- `⊗`：

```
compose((c1,o1), (c2,o2)):
    m = min(o1, c2)          # 左边留下的开括号被右边吃掉多少
    return ( c1 + (c2 - m), o1 - m + o2 )
```

- 单字节 `(` = `(0,1)`，`)` = `(1,0)`。

前缀积得到每个位置的深度（`open - close`）：

```
字节:      (      (      )      )
增量:     +1     +1     -1     -1
深度:      1      2      1      0
```

**深度是前缀和**；良嵌套语言里"栈顶 = 当前深度"，所以把括号按深度排序后，
相邻两两配对即得 `(0,3)` 和 `(1,2)`。**这就是旧 R6。**

---

## 例 3 `tree`（结合归约）：`1 + 2 + 3`

- 摘要：一段里所有整数的**和**（更一般地，`reduce(op, leaves)`）。
- `⊗`：`+`（结合）；叶子是整数 token。

```
叶子:      1      2      3
前缀和:    1      3      6
```

最后一个前缀和 = 整段的和。50000 个随机整数、随机分成 4096 块，各块先局部求和、
再合并，结果与逐个相加完全一致（`tests/test_core.cpp` 的 `test_tree_schema`）。

同一个机制在 A100 上跑 `1+2+3+…` 的大 payload：**48 GB/s**。
**这就是旧 R7**，也是 PEG 里 `e op e`、`A (op A)*` 这类递归的并行化方式。

---

## 例 4 `choice`（PEG ordered choice）：先试 A 再试 B

PEG 的 `/` = "先试第一个，成功就用它，失败才试第二个"。

- 摘要：一个带**优先级**的成功值：`(matched, rank, value)`。
- `⊗`：**谁 rank 小谁赢**（都成功时取 rank 小的；只有一个成功就取那个）：

```
compose(a, b):
   a 未成功 → b
   b 未成功 → a
   否则     → rank 小的那个
```

"取最小 rank"是结合、可交换、幂等的——**所以 ordered choice 也是幺半群**，
用同一个 `prefix_reduce` 计算。

> 这正是"PEG 不比 CFG 难"的原因：PEG 是确定性的，摘要是**一个函数/一个名次**；
> 而 CFG 的无序选择得到的是**一堆解析的集合**，更重。真正决定快慢的是摘要**可不可压缩**。
> 当各备选的首字符集在有界窗口内互不相交（判别性），choice 退化成普通 DFA，
> 与例子 1 完全一样。

## 例 5（反例）：为什么有些 PEG 不能快

考虑需要**无界回溯**的文法：某条备选先匹配了很长一段才失败，必须退回来换另一条。
这时"这段输入意味着什么"取决于还没读到的未来，摘要**无法压缩**——
没有有限/有界的 `M` 能装下它。

```
σ(i,j) = "段 [i,j) 是否派生 R"  —— 依赖 j 之后的内容
```

这种规则只能落 `interval`：在**所有子区间**上做不动点（`O(n²)`）。
它仍然正确（区间 DP / Valiant 归约到矩阵乘），但**达不到 SOTA**——
而 cuJSON/simdjson 根本不处理这类文法，所以"与它们持平"在这里没有定义。

## 一句话总览

```
解析 = Σ* 到摘要幺半群 (S, ⊗, e) 的同态        （一个同态）
并行 ⟺ 摘要可压缩                              （一个判据）
四种压缩方式 = finite / stack / tree / choice  （四个实例，同一个 prefix_reduce）
不可压缩     = interval（O(n²) 兜底，不承诺快） （一个边界）
```

旧 R1–R7 里：R1–R3 是"把有界状态写成语义元素"，R4/R6/R7 就是 finite/stack/tree 的
`prefix_reduce`，R5 是与 schema 无关的输出压缩。**它们不是七个原语，是一个原语的四个实例加一个输出阶段。**
