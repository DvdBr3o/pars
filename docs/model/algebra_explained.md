# 𝔖′ 讲解：从一个同态到四种幺半群

> 配套 `docs/model/algebra.md`。本文**按结构**讲解代数 𝔖′：先给定义，再给主定理，
> 再给唯一的判据，最后把四种 schema 用**同一套模板**逐一展开。例子只作为定义/定理的
> 插图，不是独立知识点。

---

## 1. 问题：并行解析难在哪

逐字节的朴素解析器（NBP）是一条带**状态**的顺序程序：

```
state = s0
for b in bytes:  state = T(state, b)      # 有跨字节依赖
            若命中则在结构位置 emit
```

- `T` 依赖上一个字节处理后的 `state` → **跨字节依赖**，看起来必须顺序执行；
- 结构判断（是不是引号/括号/分隔符）依赖全局状态（在不在串内、栈里有什么）；
- 栈的内容无界 → 看起来不能常数空间并行。

**目标**：把"带状态的顺序程序"改写成 **`O(n)` work、`O(log n)` depth** 的并行形式，
并**判定**哪些程序可以、哪些不行。

---

## 2. 三个定义

### 定义 1（区间摘要）

给定输入字节流 `w = b₀b₁…b_{n-1}`（语言 `Σ*`）。对一个子区间 `[i, j)`，定义它的**摘要**

```
σ(i, j) ∈ S          # 把这段字节"对解析器意味着什么"编码成 S 里的一个元素
```

`S` 是一个**幺半群**（定义 2）。摘要的直觉：一段字节的"净效果"。

### 定义 2（幺半群）

`(S, ⊗, e)`：一个集合 `S`、二元运算 `⊗ : S×S → S`、单位元 `e ∈ S`，满足

```
结合律： (a ⊗ b) ⊗ c = a ⊗ (b ⊗ c)
单位元： e ⊗ a = a ⊗ e = a
```

**结合律就是并行性的全部来源**：它允许我们**任意重新括起**一段计算，
因而不必从左到右顺序合并。

### 定义 3（解析是同态）

解析是自由词幺半群 `(Σ*, ++, ε)` 到 `(S, ⊗, e)` 的一个**同态** `σ`：

```
σ(x ++ y) = σ(x) ⊗ σ(y)          # 连接 ↦ 复合
σ(ε)      = e                    # 空串 ↦ 单位元
```

即：**先解析两段再合并**，等于**把两段的摘要复合**。

---

## 3. 主定理：解析 = 前缀积

**定理（前缀积定理）**。设 `τ_b ≜ σ(i, i+1)` 是单字节 `b` 的摘要，则

```
σ(0, n) = τ_{b₀} ⊗ τ_{b₁} ⊗ … ⊗ τ_{b_{n-1}}            （整段的摘要）
σ(0, i) = τ_{b₀} ⊗ … ⊗ τ_{b_{i-1}}                     （前缀摘要）
```

**证明**：对 `n` 归纳。`σ(0, n) = σ(0, n-1) ⊗ σ(n-1, n)`（定义 3，连接），
逐次展开即得。∎

**并行性推论**。前缀积可用 **Hillis–Steele 前缀扫描**并行计算：

```cpp
template<Summary S>
void prefix_reduce(S* p, std::size_t n) {          // O(n) work, O(log n) depth
    for (std::size_t d = 1; d < n; d <<= 1)
        for (std::size_t i = n; i-- > d;)
            p[i] = S::compose(p[i - d], p[i]);
}
```

**整个框架只有这一个原语。** 不同文法的差别只剩：`S` 是什么、`τ_b` 怎么取。
运行时状态读取也简单：**处理字节 `i` 之前的状态 = 前缀摘要 `σ(0,i)`**。

## 4. 唯一的判据：可压缩性

主定理对**任何**幺半群都成立，但 `S` 的元素可能无界，这时"并行"退化成"把整段摘要存下来"。
真正决定能否 `O(n)` 的是：

### 定义 4（可压缩）

`σ` **可压缩** ⟺ 存在一个幺半群 `M` 与满同态 `π : Σ* ↠ M`，使 `σ` 经 `M` 因子化
（`σ = ρ∘π`），且 `M` 的元素大小**有界**。

### 判据

```
可压缩  ⇒  前缀积落在有界幺半群  ⇒  O(n) work, O(log n) depth, O(1) 元素
不可压缩 ⇒  摘要无界（栈/回溯不可压缩）⇒  只能做区间不动点, O(n²)
```

**这是唯一的判据。** "一个文法能不能并行、有多快" = "它的摘要落在哪个幺半群"。
没有模式匹配，没有启发式。

## 5. 四种可压缩 schema（统一模板）

下面四种是所有"可压缩"的经典形态。每种按**同一模板**展开：
`S`（幺半群）→ `e` → `⊗` → 单字节元素 `τ_b` → 为什么可压缩 → 小例。

---

### 5.1 `finite`：有限变换幺半群（正则 / 有界状态）

| 项 | 内容 |
| --- | --- |
| `S` | 有限状态集 `Q` 上的**变换** `f : Q → Q`（`|Q|` 有界） |
| `e` | 恒等变换 `id` |
| `⊗` | 函数复合：`(g ⊗ f)(q) = g(f(q))` |
| `τ_b` | 字节 `b` 诱导的转移 `q ↦ δ(q, b)`（DFA 的转移） |
| 单字节序列 | 就是把 DFA 的转移逐字节复合 |
| 例子 | JSON 字符串：状态 `{外, 内, 转义}`，`"` 翻转、`\` 进入转义 |

**为什么可压缩**：`S` 是**有限**集合（`|Q|^|Q|`），元素是固定大小的转移表 → 有界。
**直觉**：一段字节的净效果 = 它把"入口状态"映射到"出口状态"；这个映射只依赖 `Q`，与段长无关。

```
字节:  a    "    b    "    c
τ:    保持  翻转  保持  翻转  保持
前缀积(入口状态 0):  0    0    1    1    0     →  在字符串内 = 0 0 1 1 0
```

> 对应旧 R1（分类是 `τ_b` 的构造）、R2（读前缀摘要得到"处理前状态"）、
> R3（掩码 blend 也是 `τ_b` 的构造）、R4（这个 `prefix_reduce` 本身）。

---

### 5.2 `stack`：栈幺半群（visibly-pushdown）

| 项 | 内容 |
| --- | --- |
| `S` | **栈摘要**：一段的 `(taken, given)`——进入时要从左边吃掉什么、结束时在栈上留下什么；单括号类型时退化为 `(未配对闭括号数, 未配对开括号数)` |
| `e` | `(0, 0)`（不取不留） |
| `⊗` | 归约合并（见下） |
| `τ_b` | `(` ↦ `(0,1)`；`)` ↦ `(1,0)`；其他 ↦ `(0,0)` |
| 例子 | `( ( ) )` |

单括号类型的复合律：

```
compose((c₁,o₁), (c₂,o₂)):
    m = min(o₁, c₂)                       # 左边留下的开括号被右边吃掉多少
    return ( c₁ + (c₂ - m),  o₁ - m + o₂ )
```

**为什么可压缩**：摘要是**固定大小的数对**（元素大小 O(1)），即使计数值无界也不影响并行性
——并行只需元素大小有界，不需要取值有界。
**直觉**：一段字节的净效果 = 它净消耗/净产生的括号数。

```
字节:   (      (      )      )
τ:    (0,1)  (0,1)  (1,0)  (1,0)
前缀积(取 open-close = 深度):   1      2      1      0
```

深度即前缀和；良嵌套下"栈顶 = 当前深度"，故配对 = 按深度排序后相邻配对。
> 对应旧 R5（压缩输出）与 R6（良嵌套配对）。

---

### 5.3 `tree`：结合幺半群（单自递归）

| 项 | 内容 |
| --- | --- |
| `S` | 值 + "是否命中"：`(has, v)` |
| `e` | `(false, ·)`（空段没有值） |
| `⊗` | 值上的可结合算子 `op`：`(has₁,v₁) ⊗ (has₂,v₂) = (has₁∨has₂, op(v₁,v₂))` |
| `τ_b` | 若是叶子 token（如整数）则 `(true, 值)`，否则 `e` |
| 例子 | `1 + 2 + 3`（`op = +`） |

**为什么可压缩**：摘要是**单个值**（元素大小 O(1)）。
**何时成立**：规则只有**一处自引用**且 **`op` 可结合**（`A (op A)*`、`e op e`）。
不可结合时退化为 `interval`。
**直觉**：一段字节的净效果 = 把这段里的叶子用 `op` 折叠。

```
叶子:   1      2      3
前缀和: 1      3      6       →  整段 = 6
```
> 对应旧 R7（结合递归 = 幺半群归约）；也可用 tree-contraction 处理一般树形归约。

---

### 5.4 `choice`：优先级幺半群（PEG ordered choice）

| 项 | 内容 |
| --- | --- |
| `S` | `(matched, rank, value)`：第 `rank` 个备选的成功值 |
| `e` | `(false, ·, ·)`（失败） |
| `⊗` | "第一个成功"= 对成功者取 `min(rank)` |
| `τ_b` | 一个备选在某字节上的成败/取值 |
| 例子 | `A / B`：先试 A，A 成功就用 A，否则用 B |

```
compose(a, b):
    a 未成功 → b
    b 未成功 → a
    否则     → rank 小的那个（先出现的备选优先）
```

**为什么可压缩**：摘要是**固定大小的带名次结果**（O(1)）。
**关键事实**：PEG 的 `/` **是结合的**（`(A/B)/C = A/(B/C)`），
"取最小 rank"是结合、可交换、幂等的 → 幺半群。
**边界**：这刻画的是**判别性** choice（各备选首字符集在有界窗口 `W` 内不相交）。
非判别性 choice 需要回溯，摘要无界 → `interval`。

> 这是 PEG 能保留的原因：`/` 不比 CFG 的无序并难代数化；相反，确定性让摘要更小。
> 真正决定快慢的是"摘要可不可压缩"，不是 PEG vs CFG。

### 5.5 每种 schema 的一个端到端 workload

**`finite` — JSON 字符串 `"x\"y"`（含转义）**

```
byte:        "     x     \     "     y     "
τ_b:        flip  keep  esc  consumed keep flip
state before: 0    1     1     1      1     1      (0=外,1=内,2=转义)
```
读前缀摘要 ⇒ `in = 0 1 1 1 1 1`：被转义的 `\"` 也算"在串内"，字符串内容全部被掩掉。

**`stack` — JSON 嵌套括号 `{"a":[1,2]}`**（括号 token：`{`@0,`[`@5,`]`@9,`}`@10）

```
token:   {    [    ]    }        key(open:深度-1, close:深度)
增量:   +1   +1   -1   -1
深度:    1    2    1    0        key: 0 1 1 0
按 key 稳定排序 + 相邻配对 ⇒ {0↔10}, {5↔9}
```

**`tree` — 算术归约 `1+2+3+4`**

```
叶子:     1     2     3     4
τ_b:    (T,1) (e) (T,2) (e) (T,3) (e) (T,4)      （'+' = e）
前缀积:    1     3     6    10                   整段归约值 = 10
```

**`choice` — PEG `value ::= "true" / "false" / "null" / number`，输入 `true`**

```
备选      rank   在 "true" 上
"true"      0    成功   ← 最小 rank 的幸存者
"false"     1    首字节 'f'≠'t'，失败
"null"      2    首字节 'n'≠'t'，失败
number      3    首字节非数字，失败        ⇒ 摘要 = (matched, rank=0, "true")
```

四者对照（同一模板）：`finite` 读出"在不在串内"，`stack` 读出深度→配对，
`tree` 读出归约值，`choice` 读出最小幸存 rank。**全部由同一个 `prefix_reduce` 计算。**

## 6. 四种 schema 的统一视图

| schema | `S`（元素） | 元素大小 | 可压缩的原因 |
| --- | --- | --- | --- |
| `finite` | 变换 `Q→Q` | 有界（`|Q|` 固定） | `Q` 有限 |
| `stack` | `(taken, given)` 栈摘要 | O(1) | 栈效果可压缩成定长摘要 |
| `tree` | `(has, v)` | O(1) | 存在可结合算子 |
| `choice` | `(matched, rank, v)` | O(1) | 判别性 `/` = `min` 幺半群 |

四者**都由同一个 `prefix_reduce` 计算**。运行期的一切（在不在串内、深度、归约值、
选中的备选）都是**读前缀摘要**得到的。

## 7. 从文法到 schema（编译视角）

```
PEG 文法 G
  │  [前端] 引用图分析 + FIRST_W(判别性) + 递归分类 + 幺半群模式检测
  │          → 对每条规则选一个 schema（代价函子 cost(G)）
  ▼
core::plan = { cell(schema, atom-table, mask) }
  │  [后端] 对每个 cell 取单字节元素 τ_b，一次 prefix_reduce
  ▼
结构索引 / 括号配对 / 归约值
```

**代价函子**：`cost(G) = (schema, |M_G|, work, depth, mem)`，编译器选"可精确表示且代价最低"的
schema。选择规则：
- 词法规则 → `finite`；
- 良嵌套递归（括号/call-return）→ `stack`；
- 单自递归且算子可结合 → `tree`；
- 判别性 `/` → `choice`（否则并入 `finite`）；
- 以上都不满足 → `interval`（兜底，`O(n²)`，不承诺 SOTA）。

## 8. 与旧 R1–R7 的关系

R1–R7 不是七个原语，而是**同一个构造的分解**：

| 旧 | 在 𝔖′ 中 |
| --- | --- |
| R1 分类 / R2 状态→掩码 / R3 分支→选择 | `finite` 的 `τ_b` 构造与"读前缀摘要"，不是并行原语 |
| R4 前缀状态→幺半群扫描 | **就是** `finite` 上的 `prefix_reduce` |
| R5 过滤→压缩 | 与 schema 无关的**输出算子**（popcount+scan+scatter） |
| R6 栈→良嵌套归约 | **就是** `stack` schema |
| R7 结合递归→幺半群归约 | **就是** `tree` schema |
| （新）ordered choice | `choice` schema（PEG `/`） |

**一句话**：R1–R3 把有界状态程序写成语义元素，R4/R6/R7 是三种幺半群的 `prefix_reduce`，
R5 是输出阶段。**没有七个原语，只有 `prefix_reduce`。**

---

## 9. 边界（反例：为什么有些 PEG 不能快）

考虑需要**无界回溯**的规则：某备选先匹配很长一段才失败，必须退回换另一条。
此时"这段字节意味着什么"取决于**尚未读到的未来**：

```
σ(i, j) = "段 [i,j) 是否派生 R"   —— 依赖 j 之后的内容
```

没有**有界**的 `M` 能装下这种摘要 → 不可压缩 → 只能 `interval`：在所有子区间上解不动点
（区间 DP / Valiant 归约到矩阵乘），`O(n²)` 及更高。它仍然**正确**，但**达不到 SOTA**；
而 cuJSON/simdjson 根本不处理这类文法，所以"与它们持平"在这里没有定义。

## 10. 速查（一页）

```
解析 = Σ* 到摘要幺半群 (S, ⊗, e) 的同态      （定义 3）
     = 逐字节元素的 prefix_reduce              （定理，§3）
并行 ⟺ 摘要可压缩                             （判据，§4）
四种压缩方式 = finite / stack / tree / choice （同一 prefix_reduce）
不可压缩     = interval（O(n²) 兜底，不承诺快） （边界，§9）
R1–R7 = 上述的一个分解，不是七个原语           （§8）
```
