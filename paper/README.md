# pars paper (PLDI / acmart)

LaTeX project for **“Compiling Grammars to Data-Parallel Parsers”**.  It uses
the **Tectonic v2** layout (sources in `src/`, manifest `Tectonic.toml`) and
**uv** for the figure dependencies.

## Build

```bash
# figures (uv provisions matplotlib/seaborn/pandas/scienceplots automatically)
uv run plots/make_figures.py

# PDF (tectonic fetches acmart + ACM-Reference-Format from its bundle)
tectonic -X build            # -> build/pars/pars.pdf

# or, with a full TeX Live + acmart:
latexmk -pdf -outdir=src src/main.tex
./build.sh                   # does figures + pdf in one step
```

## Python environment (uv)

`paper/` is a self-contained **uv** project, so editors get IntelliSense when you
open `paper/` as the folder:

```
paper/pyproject.toml   dependencies + [tool.pyright] config
paper/uv.lock          locked resolution (commit it)
paper/.venv/           provisioned by `uv sync` (gitignored)
paper/.vscode/         points the editor at .venv and adds plots/ to analysis
```

```bash
cd paper
uv sync                    # create/refresh .venv
uv run plots/make_figures.py
```

### Linking with a root uv workspace

uv supports **workspaces**: a single root environment + lock shared by members.
Add a `pyproject.toml` at the repository root with

```toml
[tool.uv.workspace]
members = ["paper"]
```

then run `uv sync` at the root; uv manages one `.venv`/`uv.lock` for all members
(you can delete `paper/.venv`, and point editors at the root venv with
`[tool.pyright] venvPath = ".."`, `venv = ".venv"`).  Because the repo root is a
C++/xmake project, we keep `paper/` self-contained by default; add the root
workspace file only if you want one shared Python environment.

## Figures (uv + matplotlib + seaborn + SciencePlots)

`plots/paperplots.py` is organised so a human can tweak figures easily:

- **CONFIG** (top): paths, labels, palette, figure sizes — the only place to
  edit for restyling.
- `load_*` : read `plots/data/*.csv`.
- `figure_*`: one function per figure, each returns a matplotlib `Figure`:
  - `figure_sota`         grouped bars, min–max whiskers, log y (device vs
                          chunked vs SOTA, by format);
  - `figure_scaling`      per-format facets, throughput vs input size, error bars;
  - `figure_stages`       stacked P1–P4 time breakdown;
  - `figure_distribution` p50 with min–max whiskers.

Dependencies are declared inline in `make_figures.py` (PEP 723) and managed by
uv — no `requirements.txt`.

## Regenerating benchmark data (deterministic, via xmake)

```bash
xmake build paper_data                 # scales/iters from xmake options
xmake f --scales=16,64,256 --iters=10  # full run
xmake build paper_data
```

This writes `paper/plots/data/{pars,baselines,stages}.csv`.  No environment
variables are used; configuration goes through xmake options.
